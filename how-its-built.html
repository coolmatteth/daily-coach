How it's built

Five scheduled Claude agents, each owning one job, coordinating through Notion. Nothing reaches the athlete's phone except through a worker that enforces the rules in code. The whole thing is a loop. What you do today is what tomorrow's plan is built from.

Grounding over prompting. The planner works from an Athlete File: profile, working weights, injury state, current training block. A second agent keeps that file current by rescanning the logs weekly. The daily calendar sync exists so the planner always knows what day it is and what was actually trained.

The model proposes, code disposes. Safety-relevant rules are not trusted to the model. A deterministic worker re-checks PR timing against dated windows, rejects duplicate or late deliveries, restores required exercises a plan dropped, and caps spend. The model never has to guess whether the athlete trained yesterday. Edit timestamps on the worksheet answer that.

Tested like software. Fifteen eval scenarios run before any prompt or model change ships. Each one is rebuilt from a real mistake the system once made. The suite taught an honest lesson on its first day. Every reasoning scenario passed while production failed in layers the tests never touched, like stale data and duplicate sends. New scenarios now come from real incidents, and the deterministic gates outrank the eval.

The demo on the front page runs the same programming rules against a generic profile. Its 80 input combinations are pregenerated, so the demo has zero moving parts.
